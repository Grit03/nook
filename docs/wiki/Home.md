# nook 백엔드 의사결정

nook 백엔드를 만들면서 내린 결정을 모아 둔 위키입니다. 각 결정은 **무엇을 고민했고, 무엇을 골랐고, 왜 골랐는지**, 그리고 **지금 코드 어디에 남아 있는지**를 적습니다.

## 먼저 알면 좋은 것

nook은 지도에 보이는 영역 안의 작은 숙소(스테이, stay)를 찾아 주는 서비스입니다. 백엔드는 세 가지 일을 합니다.

| 하는 일 | 쓰는 기술 |
| --- | --- |
| 회원가입, 로그인, 로그인 유지 | JWT, Redis, Argon2 |
| 지도 영역 안의 스테이 검색 | MySQL 공간 인덱스(spatial index) |
| 스키마 관리와 테스트 데이터 생성 | TypeORM 마이그레이션(migration), 시더(seeder) |

자주 나오는 용어:

- **NestJS(네스트)**: Node.js 서버 프레임워크. 기능을 모듈(module) 단위로 나누고, 요청 앞단의 검사는 가드(guard), 입력 검증은 파이프(pipe)가 맡습니다.
- **TypeORM**: TypeScript 클래스(엔티티, entity)로 테이블을 정의하는 ORM. 클래스의 데코레이터(`@Column` 등)가 곧 스키마입니다.
- **JWT(JSON Web Token)**: 서버가 서명한 토큰. 서버가 세션을 저장하지 않아도 토큰만 보고 사용자를 알 수 있습니다.

## 읽는 법

각 결정은 같은 틀로 적었습니다.

- **상황**: 무엇이 문제였나
- **선택**: 무엇을 골랐나 (검토한 대안 포함)
- **이유**: 왜 그걸 골랐나
- **코드**: 지금 어디에 있나
- **남은 과제**: 알고도 아직 안 한 것, 다음에 바꿀 것
